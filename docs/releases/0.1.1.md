# 0.1.1 — Walk-in checkout and opening inventory

14 October 2026 (Asia/Kabul).

- Walk-in is selected by default. Cash now contains the actual exact amount due, rather than showing a misleading placeholder while submitting zero. Manual tender amounts remain editable and full payment is still required for walk-in sales.
- The POS customer dialog searches names/phone numbers, always offers Walk-in, and offers Add customer to authorized employees. The shared customer form selects the newly saved account without losing the cart.
- New-product opening stock is beside the unit/pricing details with a zero default and base-unit guidance. Inventory also offers Add product. Existing stock movements/validation remain authoritative.
- Receipts identify the customer, including Walk-in. New interface text is translated into Dari.

## Verification

- 12 frontend tests passed, including six checkout/opening-inventory regression scenarios.
- 21 Rust/SQLite integration tests passed, including opening quantity → walk-in sale → newly created customer sale, with stock, cash and debt assertions.
- TypeScript/Vite production build passed; the existing large-chunk advisory remains.
- Browser UI with the real local Rust/SQLite demo adapter: created QA opening rice with 12.5 kg at AFN 100.50/kg; completed walk-in receipt RD-000093 with exact cash; created QA POS customer from an empty search and completed RD-000094. Each sale removed 1 kg, leaving 10.5 kg. No real-store records were used.
- Customer picker, opening-stock form and walk-in receipt screenshots are under `docs/screenshots/` with the `1014` suffix.
